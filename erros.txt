CRÍTICOS — Causam crash, falha de deploy ou vulnerabilidade de segurança
C1 — XSS em criar_linha_html (app_streamlit.py, linha 63)
O que é: XSS (Cross-Site Scripting) significa que dados de uma fonte externa são inseridos diretamente no HTML sem "limpeza".

O problema:


VS
Lines 57-65
def criar_linha_html(items):
    safe_items = [str(item) if item is not None else '' for item in items]
    return "<tr>" + "".join(f"<td>{item}</td>" for item in safe_items) + "</tr>"
O nome safe_items é enganoso — a lista não foi higienizada. Se o Gemini retornar um valor como <b>teste</b>, ele vai renderizar como HTML em negrito. Se retornar <script>alert(1)</script>, esse código executa no navegador.

Os campos detalhe nas linhas 100 e 116 fazem escape manual parcial (só < e >), mas faltam &, ", ' — o módulo html.escape() do Python faz isso corretamente.

Impacto: Segurança. Dados da IA são injetados diretamente no HTML renderizado pelo Streamlit.

C2 — requirements.txt com versão errada do PyMuPDF
O que é: O requirements.txt especifica uma versão que já foi comprovada como quebrada.


VS
Lines 1-7
streamlit==1.32.0
...
PyMuPDF==1.26.0
A versão 1.26.0 tinha o libmupdf.dylib ausente, causando o ImportError que acabamos de corrigir. Ao fazer push para o GitHub e o Streamlit Cloud instalar as dependências, ele vai instalar 1.26.0 novamente e o erro voltará.

Impacto: Deploy quebrado imediatamente no Streamlit Cloud.

C3 — extrair_imagem_pagina abre e fecha o PDF em cada iteração (app_streamlit.py, linha 213)
O que é: Uma operação cara (abrir um arquivo grande) é repetida dentro de um loop.


VS
Lines 496-511
for page_num in paginas:

E dentro de extrair_imagem_pagina:


VS
Lines 212-225
def extrair_imagem_pagina(pdf_path: str, page_num: int) -> bytes | None:
    try:
        doc = fitz.open(pdf_path)   # ← ABRE o PDF inteiro
        ...

Para um decreto com 15 páginas de Excesso de Arrecadação, o PDF é aberto e fechado 15 vezes. O sistema operacional tem limite de arquivos abertos simultâneos e cada abertura lê o arquivo inteiro do disco.

Impacto: Lentidão severa na galeria de anexos. Risco de erro too many open files em PDFs grandes.

M1 — carregar_processadores() sem cache (recria objetos a cada análise)

VS
Lines 250-255
def executar_processamento(pdf_path: str, texto_total: str):

E carregar_processadores faz:


VS
Lines 41-51
def carregar_processadores():
    api_key = os.getenv("GEMINI_API_KEY")
    genai.configure(api_key=api_key)
    model = genai.GenerativeModel(model_name)
    p1 = P1Processor(model)  # compila todos os regex do P1
    p2 = P2Processor(model)  # compila todos os regex do P2

Cada clique em "Analisar" reconstrói os 3 processadores com todos os regex compilados e reconfigura a API do Gemini. O decorator @st.cache_resource existe exatamente para evitar isso.

Impacto: Processamento desnecessariamente mais lento a cada análise.

M3 — Recursão para retentativas em _call_gemini (P1, P2, P3)

VS
Lines 182-189
        except Exception as e:
            logger.error(
                "Erro na chamada da API ou JSON (Tentativa %d): %s", tentativa, e
            )
            time.sleep(5)
            return self._call_gemini(
                prompt, contexto, imagens, tentativa + 1, max_tentativas
            )
Retentativas implementadas como chamada recursiva. Com max_tentativas=3, a profundidade é pequena e não causa stack overflow, mas é uma prática ruim. Se alguém mudar max_tentativas para 100, o programa crasha com RecursionError. O padrão correto é um for loop.

Impacto: Risco latente, má prática e difícil de depurar.

M5 — Comentário desatualizado em pdf_to_txt.py (linha 95)

M6 — identificar_padrao_global dispara P2 com apenas 1 ocorrência de "REDU." (processamento_txt.py, linha 280)

VS
Lines 280-281
    if tem_titulo_p2 or tem_rodape_p2 or contagem_redu >= 1:
        return "P2"
Uma única palavra "REDU." em qualquer lugar do documento força o processador P2 para todos os decretos do arquivo. Se um decreto P1 mencionar acidentalmente "REDU." (por erro de OCR, por exemplo), o arquivo inteiro será processado errado.

O comentário na linha 274 reconhece o problema: "Evita falso positivo se aparecer só uma vez" — mas o threshold continua em >= 1, não em >= 2.

Impacto: Classificação incorreta do tipo de decreto, gerando extrações erradas.
